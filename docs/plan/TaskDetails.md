## 0. 前置调研：确定失败补偿契约 (Task V0)

**优先级**：🔴 P0

**状态**：✅ 已完成

**估时**：已完成

**依赖**：`docs/audit/Findings.md`、A03 审计结果、`ARCHITECTURE.md`、`src/git.js`

**背景**：Git 分支和 HEAD 可以恢复，但任意 `post_hooks` 可能修改仓库外系统，因此不能宣称整个进程具备强事务语义。

**目标**：
- 将自动补偿限定为引擎可证明拥有的仓库路径和 Git 工作区状态
- 为无法自动完成的补偿生成稳定、机器可读的恢复动作
- 保留 Hook 外部副作用这一显式风险，不以成功日志掩盖

**调研产出**：
- Create: `docs/plan/TaskDetails.md` — 记录补偿策略、实现步骤、验收和远期边界

**Steps:**
- **Step 1: 对齐证据**
  - 以 AUD-005 的两仓失败探针和安全沙箱产品约束为输入。
- **Step 2: 选择补偿策略**
  - 每个实际开始变更的仓库保存是否存在、原 HEAD 和原分支状态。
  - 失败时按触及顺序的逆序执行补偿；新克隆目录删除，已有仓库恢复原 checkout 和 HEAD。
- **Step 3: 确定报告边界**
  - 错误对象携带失败仓库、原始原因、每项补偿状态、可执行恢复动作和已执行 Hook。
  - Hook 的外部副作用只报告，不进行未经声明的猜测性清理。

## 1. AUD-005 核心开发计划

### Task K1: 实现多仓失败逆序补偿

**优先级**：🔴 P0

**状态**：✅ 已完成

**估时**：当前修复周期

**依赖**：V0，现有全仓 dirty gate 和仓库路径 containment 校验

**背景**：`checkoutWorkspace` 当前在循环中直接修改仓库，后续异常会让已经处理的仓库保持目标状态。

**目标**：
- 在首次写操作前捕获最小恢复快照
- 对当前失败仓库和前序仓库逆序补偿
- 补偿自身失败时继续处理其余仓库并完整汇总结果

**Files:**
- Modify: `src/git.js` — 捕获快照、跟踪触及记录、执行逆序补偿并抛出结构化错误
- Test: `test/git-rollback.test.js` — 覆盖新克隆移除、已有仓库 HEAD/分支恢复及报告内容

**Steps:**
- **Step 1: 建立失败注入回归**
  - 使用仅位于系统临时目录的本地 Git fixtures，让第二仓在第一仓变更后稳定失败。
- **Step 2: 实现补偿器**
  - 新目标只在本次开始前不存在时允许递归移除。
  - 已有仓库使用参数数组恢复原分支或游离提交，再 hard reset 到原 HEAD。
  - 每项补偿独立捕获错误，防止一个恢复失败阻断其余恢复。
- **Step 3: 验证**
  - 运行聚焦回归、quick、全量测试和 full 验证，并进行路径与 destructive call-chain 复核。

## 4. 风险与维护规则

- **递归删除边界**：只能删除路径 containment 已验证且事务开始前不存在的仓库目标。
- **已有仓库恢复**：恢复 checkout 和 HEAD，不承诺撤销 fetch 更新的远端引用。
- **Hook 副作用**：记录已尝试的 Hook；未声明逆操作时不自动清理仓库外资源。
- **进度同步**：任何任务状态变化后，同步更新 [Dashboard.md](Dashboard.md) 的需求索引表状态。
